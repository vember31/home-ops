# SparkyFitness

Family fitness, food, water, and health tracking (frontend nginx + Node.js server).
Runs in the `fitness` namespace, reachable at https://fitness.${SECRET_DOMAIN}.
Public via Cloudflare (proxied) -> Traefik.

## GitLab CI/CD Variables

Create a `sparkyfitness` variable group (or individual vars) in GitLab with:

| Variable | Purpose |
|---|---|
| `SPARKYFITNESS_POSTGRES_USER` | Database owner role (`sparky`) — used for migrations |
| `SPARKYFITNESS_POSTGRES_PASS` | Password for the above |
| `SPARKYFITNESS_APP_DB_USER` | Limited app role (e.g. `sparky_app`) |
| `SPARKYFITNESS_APP_DB_PASS` | Password for the above |
| `SPARKYFITNESS_API_ENCRYPTION_KEY` | 64-char hex (`openssl rand -hex 32`) — persistent, never rotate casually |
| `SPARKYFITNESS_BETTER_AUTH_SECRET` | Long random secret — do **not** rotate once 2FA is enabled |
| `SPARKYFITNESS_ADMIN_EMAIL` | (optional) email of a user auto-granted admin on startup |

`POSTGRES_SUPER_PASS` is pulled from the existing `cloudnativepg` variable group.

The OIDC client ID/secret + issuer are generated by the pocket-id operator's
`PocketIDOIDCClient` CR (`sparkyfitness-oidc-credentials` secret), not GitLab.

## Database

Uses the shared `postgres-18` CNPG cluster. The `postgres-init` init container
creates the `sparkyfitness` database owned by `SPARKYFITNESS_POSTGRES_USER` with
**CREATEROLE** (no superuser). On first boot the server runs its migrations,
auto-creates the limited `SPARKYFITNESS_APP_DB_USER` role, applies RLS policies,
and grants it table/schema permissions.

If migrations ever fail with missing privileges, raise the role to
`--superuser` in the init container's `INIT_POSTGRES_USER_FLAGS` (matches
upstream compose behavior), re-apply, then revert after the schema settles.

## OIDC

Login is OIDC-only via Pocket ID (email/password disabled, auto-redirect on).
The env-configured provider slug is `sparkyfitness`:

- issuer: pocket-id discovery (from the operator-generated secret)
- redirect URI: `https://fitness.${SECRET_DOMAIN}/api/auth/sso/callback/sparkyfitness`
  (this path is verified against the server source — it is **not** the generic
  `/api/auth/callback/...`)
- auto-register: on — first login by a user in the `sparkyfitness-users` group
  creates their account

Access is restricted to the `sparkyfitness-users` group (dm, emm) in pocket-id.

## Startup

First boot runs DB migrations and can take a few minutes. The server's
startup probe allows up to 10 minutes; watch with:

```bash
kubectl -n fitness logs deploy/sparkyfitness -c server -f
```

Health endpoint: `GET /api/health` on :3010 (server) and `/` on :8080 (frontend).
Nginx runs non-root on 8080 (`NGINX_LISTEN_PORT`). Public traffic is
Cloudflare-proxied, so `SPARKY_FITNESS_REAL_IP_HEADER=CF-Connecting-IP` is set
(plus `SPARKY_FITNESS_TRUSTED_PROXY_HOPS=2` as fallback) for correct per-IP
rate limiting; the server is never reachable without the CDN, so the header
cannot be spoofed. Gatus monitors the public URL via 1.1.1.1.
